**实测观察到的 Agent 行为**（真实输出摘录）：

- 候选人把线程池答成 HashMap 时，面试官 Agent 判断："他完全答偏了……得先礼貌拉回来，重新问 HashMap 的核心结构。"
- 候选人回答"不会"时，Agent 自主降难度："候选人坦诚说不会，先不深挖，换一道更贴近日常开发的题。"
- 最后一题，Agent 自主收尾："最后一题了，源码追问没意义，降到实战场景看他有没有基本的锁使用直觉，然后收尾。"
- 评估官先调用统计工具再下结论，未凭空打分。

## 5 缺陷与修复记录（本轮复盘）

| 编号 | 缺陷 | 影响 | 根因 | 修复 |
|------|------|------|------|------|
| B1 | 服务进程偶发退出（exit code 1），面试中断 | 高 | Node 默认行为：未捕获异常 / 未处理 Promise 拒绝直接终止进程 | 增加 `uncaughtException` / `unhandledRejection` 兜底，只记录不退出 |
| B2 | 大模型单次网络抖动导致面试官退化成固定话术 | 中 | LLM 调用无重试 | 网络类失败 / 超时 / 5xx 自动重试一次；配置类与 4xx 直接抛出 |
| B3 | 端口被占用时抛出英文调用栈 | 低 | 未监听 `server.on('error')` | 输出可操作中文提示后退出 |
| B4 | Agent 工具轨迹跨轮累积 | 高 | `s.agentTrace` 用 concat 累积 | 每轮决策开始重置，避免 prompt 膨胀导致模型退化 |
| B5 | 面试无法结束 | 高 | Agent 动态换题使 `plan` 无限增长 | 终止边界固定为会话创建时的 `planSize`；收尾阶段禁用换题 |
| B6 | 最后一题被判为追问，多问一轮 | 中 | 意图判定缺少"是否还有下一题"约束 | `canFollowUp` 追加 `hasNext` 条件 |
| B7 | 评估官输出"待核对数据后给出"占位结论 | 中 | 最后一步仍在调工具未给结论 | 结果校验 + 重试一次；最后一步强制输出 final |
| B8 | Chrome 语音识别 `network` 错误 | 高 | 内置识别依赖境外服务 | 集成本地离线识别引擎，并保留浏览器回退 |
| B9 | 两段对话黏连重复 | 中 | 端点检测与缓冲清理时序 | 端点静音 0.8s + 结果去重 + 提交即清缓冲 |
| B10 | `.bat` 中文导致 cmd GBK 乱码报错 | 中 | 编码问题 | 脚本统一为纯 ASCII |
| B11 | 提交后引擎异步 `onerror` 空指针 | 低 | 状态已清空仍回调 | `onerror` 开头判空返回 |
| B12 | 候选人说「哈 map」既未纠成 HashMap，面试官还臆断成「MQ」 | **高** | ①词条表只收整词变体，覆盖不了「中文谐音+空格+英文」的口语混读；②Agent 遇到认不出的术语会自作主张替换 | 新增 40 条口语混读正则层（长词优先）+ 服务端三重归一兜底；Agent 系统提示加「认不出就原话复述，严禁替换为另一个技术名词」硬约束 |
| B13 | 修改归一变量作用域导致 `answer is not defined`（回归发现） | 中 | 变量在分支内声明却在另一分支使用 | 提到函数顶部统一声明，重启后复用上方 A/B 用例复测通过 |

## 6 测试结论

1. **功能完整性**：需求规格说明书中 A1~A7 七项验收标准全部满足——语音闭环、Agent 决策可见、多 Agent 产出、MCP 联调、离线可用、一键部署、回归通过。
2. **质量水平**：协议层、接口层、端到端、AI 行为四类测试在本轮全部通过；AI 安全三类边界实验均通过。
3. **跨语言一致性**：Python Agent 端 31 例实测全部通过，Node 端与 Python 端行为一致。
4. **遗留项**：中文神经语音音色依赖操作系统语音包，不同机器音色表现存在差异（已内置自动降级）。
