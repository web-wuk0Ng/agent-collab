## 3 题库模块（lib/bank.js，126 行）

### 3.1 数据结构

```json
{
  "id": "java-001",
  "type": "tech",            // tech | project | scenario | behavior
  "text": "说说 HashMap 的底层结构",
  "keywords": ["数组", "链表", "红黑树", "扩容"],
  "points": ["数组+链表+红黑树", "扩容机制", "hash 扰动"],
  "hint": "先讲结构，再讲扩容，最后讲线程安全"
}
```

### 3.2 组卷算法（`buildPlan`）

```
1. 按题型定义展示顺序：tech → project → scenario → behavior
2. 每一层内部使用 Fisher-Yates 洗牌：
   for i from n-1 down to 1:
       j = random(0..i); swap(a[i], a[j])
3. 按层拼接，取前 N 题组成 plan
4. 固化 planSize = plan.length（作为面试终止边界）
```

**为什么分层再洗牌**：既保证"先技术、后项目、再场景、最后行为"的面试节奏，又保证每次题目不同，避免学生背答案。

### 3.3 关键函数

| 函数 | 说明 |
|------|------|
| init() | 加载 `data/questions/*.json`，建立岗位索引 |
| positionsMeta() | 返回岗位名、题量、题型分布 |
| getBank(position) | 取岗位题库对象 |
| buildPlan(position, n) | 组卷，返回带 index 的题目序列 |
| findQuestion(position, id) | 按 ID 取完整题目（含 points/hint） |

## 4 检索增强模块（lib/rag.js，79 行）

### 4.1 切片策略

按 Markdown 二级标题（`## `）切片，剔除正文少于 30 字的碎片，标题作为片段名。

### 4.2 分词

- 英文：正则 `[a-z][a-z0-9+.#/-]{1,}`，统一小写（保留 `C++`、`Node.js`、`CI/CD` 等形态）；
- 中文：去除非汉字字符后按 **2-gram** 切分（"红黑树" → "红黑"、"黑树"）。

### 4.3 打分（BM25）

```
score(q, d) = Σ_t idf(t) * (tf(t,d) * (k1+1)) / (tf(t,d) + k1 * (1 - b + b * len(d)/avgLen)) * tf(t,q)
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
k1 = 1.5, b = 0.75
```

返回 top-k（默认 4）且 `score > 0` 的片段，拼装为 `【参考资料N·标题】正文` 注入提示词。

### 4.4 设计取舍

未引入向量模型的原因：避免额外的模型文件与依赖，保持"零依赖 + 可离线"；对面试场景的短查询，BM25 的召回质量已足够，且响应为毫秒级。

## 5 术语归一模块（lib/terms.js，170 行）

### 5.1 问题背景

语音识别常把技术名词听错："瑞迪斯"→Redis、"麦斯扣"→MySQL、"威优"→Vue、"叉叉 L"→XML。直接拿去评估会误判"答非所问"。

### 5.2 策略

1. **中文音近词映射**：130+ 条字典，替换后用于评估与展示；
2. **ASCII 词边界大小写归一**：`jvm` → `JVM`、`redis` → `Redis`；
3. **防误伤**：仅在词边界匹配，避免把 `test` 中的 `es` 误改、`Elasticsearch` 被改坏。

### 5.3 接入位置

语音识别返回文本后统一 `normalize()`，保证进入 Agent 与评估环节的文本是干净的。

## 6 语音识别模块（lib/asr.js，131 行）

### 6.1 模型与参数

| 参数 | 取值 | 说明 |
|------|------|------|
| 模型 | sherpa-onnx streaming zipformer 双语（中英）2023-02-20 | 支持"说 Redis 这类英文词" |
| 量化 | int8 | 体积与速度平衡 |
| 线程数 | 4 | 实测 RTF 0.041 |
| 采样率 | 16000 Hz | 单声道 |
| 端点检测 | 静音 0.8s | 判定"这句话说完了" |

### 6.2 会话隔离

```js
const streams = new Map();   // id -> { stream, lastText }
```

每个会话独立 stream，避免多人并发时音频互相污染；stream 数量超过 20 时淘汰最早的一个，防止内存泄漏。

### 6.3 关键函数

| 函数 | 说明 |
|------|------|
| available() | 引擎是否可用（懒加载，失败后记忆错误避免反复重试） |
| push(id, pcm) | 接收 16-bit PCM，转 Float32 归一化后喂入，返回 final / interim / endpoint |
| finish(id) | 结束音频，做最终解码，返回经术语归一的完整文本 |

### 6.4 两级回退

```
本地引擎可用 → 使用本地引擎（离线可用、识别快）
本地引擎不可用 → 浏览器 Web Speech API
两者都不可用 → 提示用户改用键盘输入（流程仍可完成）
```

## 7 面试官 Agent 运行时（lib/agent.js，254 行）

### 7.1 设计定位

与"模板软件"的本质区别：

| 类型 | 决策方式 |
|------|----------|
| 模板软件 | `if (回答短) 追问 else 下一题` —— 固定输入输出 |
| Agent | 每轮由大模型自主思考，并可调用工具获取信息后再决定 |

### 7.2 工具集

| 工具 | 参数 | 真实行为 |
|------|------|----------|
| analyze_answer | answer | 调用大模型，输出命中要点、缺失要点、深度 1-5、是否含糊、建议追问点 |
| search_knowledge | query | 真实 BM25 检索岗位知识库 |
| find_question | topic、type | 从未问题目中按知识点匹配挑题（收尾阶段禁用） |
| record_observation | note、tag、topic | 写入会话记忆，影响后续提问与最终报告 |
| adjust_plan | action、reason | 记录 deepen / skip / switch 决策 |

### 7.3 主循环

```
decide(s, opts):
  if 未配置大模型: return offlineFallback()
  trace = []; s.agentTrace = []        // 每轮重置，避免提示词膨胀
  for step in 0..2:
      lastStep = (step == 2)
      messages = [system] + trace
      if lastStep: 追加"最后一步，必须给出 final"
      j = LLM(messages, jsonMode)
      thought = j.thought
      if !lastStep and j.action:
          obs = TOOLS[j.action.tool](s, j.action.args)
          s.agentTrace.push({ step, thought, tool, args, observation: obs })
          trace.push("[工具返回] " + JSON(obs).slice(0, 900))
          if j.final: break
          continue
      if j.final: final = j.final; break
  return { line: final, thought, trace, steps }
```

### 7.4 提示词要点

- 角色设定：某岗位资深面试官，"不是在念脚本，要边听边思考"；
- 输入上下文：当前题、考察点、候选人回答（截取 1500 字）、已问题目、历史观察（最近 6 条）、进度；
- 策略空间：deepen（深挖）/ probe（换角度）/ switch（换知识点或降难度）/ next（点评后下一题）；
- 约束：最后一题禁止换题；已追问过一次不得追问第二层；final 为口语化中文，1~3 句，不念题号、不给标准答案。

### 7.5 兜底逻辑（`offlineFallback`）

无大模型或输出非法时启用：回答过短（<50 字或零关键词命中且 <150 字）→ 追问；否则（已追问过 / 最后一题 / 回答充分）→ 推进下一题。保证任何情况下面试都能走完。

## 8 多 Agent 团队（lib/agentTeam.js，276 行）

### 8.1 角色

| 角色 | 职责 | 产出字段 |
|------|------|----------|
| 面试官 | 主持对话、追问换题 | 对话内容 |
| 评估官 | 复核逐题表现、修正评分 | agentVerdict、agentPerQuestion、agentHighlights、agentGaps |
| 陪练官 | 生成提升计划 | coachPlan（3~7 天安排 + 针对性练习题） |
| 出题官 | 按 JD 出题 | 题目与考察点 |

### 8.2 统一运行时（`runRole`）

与面试官 Agent 共用"思考 → 工具 → 观察 → 结论"循环，额外增加：

1. **结果校验**：`ctx.validate(final)` 判定产出是否合格（如禁止"待核对数据后给出"这类占位结论）；
2. **失败重试**：校验不通过时把错误原因回灌再生成一次；
3. **强制结论**：最后一步不允许再调工具，必须输出 final；
4. **工具集**：评估官可用 `stat_rounds`（统计逐题指标）、`read_answer`（读原话）、`lookup_points`（查考察点）。

### 8.3 收尾编排（`finalize`）

```
baseReport = 规则引擎评分（多维度）
[评估官, 陪练官] = await Promise.all([...])     // 并行，缩短出报告时间
报告合并：
  scoreAdjust 逐维度限幅 ±15 后应用
  重算 overall = 各维度均值
  写入 agentVerdict / agentPerQuestion / coachPlan
```

### 8.4 关键陷阱（已修复）

| 问题 | 现象 | 修复 |
|------|------|------|
| 轨迹跨轮累积 | prompt 膨胀，第 6 轮起模型退化成规则兜底 | 每轮 `s.agentTrace = []` 重置 |
| 动态换题撑长计划 | 面试永远结束不了 | 终止边界固定 `planSize`，`canSwitch=false` 时禁止换题 |
| 最后一题被判为追问 | 多问一轮、无法收尾 | `canFollowUp` 增加"必须还有下一题"条件 |
| 输出占位结论 | 报告出现"待核对数据后给出" | 结果校验 + 重试一次，仍不合格则保留初版 |

## 9 面试状态机（lib/interview.js，273 行）

### 9.1 状态定义

| 状态 | 含义 |
|------|------|
| active | 进行中 |
| finished | 已结束并出报告 |

### 9.2 关键函数

| 函数 | 说明 |
|------|------|
| start(s, opts) | 组卷（写入 planSize）、生成开场白与首题；支持 JD 定制 |
| handleAnswer(s, p) | 核心流转：记录回答 → 更新指标 → Agent 决策 → 返回下一句/下一题 |
| prefetch(s, p) | 并行预取下一步内容，签名 = 答案前 60 字 |
| generateReport(s) | 规则评分 + 多 Agent 复核 + 陪练计划 |
| briefTrace(trace) | 精简轨迹下发前端（控制体积） |

### 9.3 作答流转判定

```
if 是追问回答:
    记录到 followUps，直接进入下一题
else:
    Agent 决策 → wantsNext?
        ├─ 否 且 未追问过 且 还有下一题 → 追问（followCount++）
        └─ 是 → 进入下一题（优先使用 Agent 动态挑的题）
```

### 9.4 进度计算

分母恒为 `planSize`（会话创建时固化），不随 Agent 换题变化，避免"题目越做越多"的观感。

### 9.5 预取机制

```
学生开口 → 前端投递 prefetch 请求（带答案前 60 字签名）
服务端并发生成下一步内容并缓存
学生提交 → 签名一致则直接复用（1120ms → 6ms），不一致则重新生成
```

### 13.2 语音采集（public/js/localasr.js，162 行）

```
AudioContext(sampleRate 16000)
 → ScriptProcessor(2048 帧)
 → 累积约 160ms 后打包 Float32 → Int16 → base64
 → POST /api/asr/chunk（每 160ms 一片）
 → 收到 endpoint 或命中结束词 → POST /api/asr/end
```

### 13.3 自动提交判定（public/js/app.js）

1. **端点检测**：服务端返回 endpoint（静音 0.8s）；
2. **结束词字典**：60+ 词条（"不会"、"不知道"、"就这些"、"讲到这里"、"源码没看过"…），**仅判定句尾 14 字**，避免句中"不知道"被误判为说完；
3. 提交后清空缓冲，并对同一段文本去重，防止两段对话黏连。

### 13.4 打断控制

| 场景 | 空格键行为 |
|------|-----------|
| 面试官讲话中 | 立即打断，停止朗读，交还发言权 |
| 学生作答中 | 立即提交当前已识别内容 |

### 13.5 Agent 工作台渲染

展示 4 个角色卡（面试官 / 评估官 / 陪练官 / 出题官，活跃时点亮）与决策卡：第 N 次决策、思考内容、调用的工具（中文化）、工具返回值摘要、最终说的话。

### 13.6 隐私设计

- 摄像头帧仅在本地推理，统计结果（抬头率、紧张度）才上报；
- 语音识别优先本地引擎；
- 界面不展示"语音在本地处理"等易引起疑虑的提示（按用户要求隐藏），也不展示中间识别文本，避免干扰作答。

## 14 错误处理总表

| 层级 | 错误类型 | 处理策略 |
|------|----------|----------|
| 前端 | 麦克风无权限 | 引导重新授权，提供重试入口 |
| 前端 | 识别引擎不可用 | 自动回退浏览器识别 |

| 接口层 | 请求体过大 | 断开连接，返回错误 |
| 接口层 | 路径穿越 | 403 |
| 领域层 | 大模型超时/失败 | 重试一次 → 降级离线面试官 |
| 领域层 | Agent 输出非法 | 规则兜底，保证流程继续 |
| 领域层 | 报告 Agent 产出占位 | 校验 + 重试，仍不合格保留初版 |
| 存储层 | 解析失败 | 隔离损坏文件并重建 |
| 进程层 | 未捕获异常 | 记录日志，保持存活 |
