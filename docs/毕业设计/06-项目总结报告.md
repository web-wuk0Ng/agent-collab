## 1 项目概况

「面镜 MockMirror」是一套面向高校学生的 AI 模拟面试与能力提升软件。系统以**全语音交互**还原真实面试场景，由**自主决策的面试官 Agent**主持追问、换题与收尾，面试结束后由**评估官与陪练官 Agent**联合产出逐题复盘与一周提升计划，并通过 **MCP 协议**把面试能力开放给第三方 AI 工具调用。

## 2 技术方案要点

### 2.1 为什么不上桌面端

曾评估 Electron / Tauri 桌面化方案，最终放弃。理由：

1. 打包后体积 100MB+，且不同平台打包失败风险高；
2. 评审与使用者需要"clone 后双击即跑"，桌面端安装门槛反而更高；
3. 演示场景需要摄像头、麦克风、大屏投影，浏览器原生支持最好。

结论：**把成本投入到 Agent 能力本身**，而不是外壳。

### 2.2 让 Agent 真正"可看见"

多数所谓 AI 面试只是"大模型接一句话"。本系统把 Agent 的运行时显式化：

```
观察（拿到回答与上下文）
  → 思考（thought，会展示给使用者）
  → 调用工具（analyze_answer / search_knowledge / find_question /
              record_observation / adjust_plan）
  → 观察工具返回
  → 再思考 → 输出最终话语
```

每一步都会在界面「Agent 工作台」实时呈现，使用者能看到"它在想什么、查了什么、因此说了什么"。

### 2.3 让能力"可外接"

通过零依赖的 MCP Server，把主持面试的能力暴露为标准工具，Claude Desktop、Cursor 等外部 AI 可以直接调用完成一场面试并取回报告——从"一个网站"变成"可被其他 Agent 使用的能力节点"。

### 2.4 关键工程决策

| 决策 | 理由 |
|------|------|
| 服务端零第三方依赖 | 消除安装失败与环境差异，实现"clone 即跑" |
| 单文件 JSON 存储 + 原子写 | 免安装数据库，且写一半崩溃不损坏数据 |
| 终止边界固化 planSize | 允许 Agent 换题，但不允许把面试无限延长 |
| 本地语音识别 + 浏览器回退 | 解决国内 Chrome 内置识别 `network` 错误 |
| 预取机制 | 把响应延迟从 1.12s 压到 6ms，对话不卡顿 |
| 结果校验 + 重试 | 杜绝评估官输出"待核对数据后给出"这类占位结论 |
| 进程级异常兜底 | 任何未捕获异常只记录不退出，保证 20 分钟的面试不中断 |

## 4 开发过程复盘

### 4.1 需求演进

| 阶段 | 关键诉求 | 应对 |
|------|----------|------|
| 起步 | 能在 Chrome 上语音面试 | 集成本地离线识别引擎 |
| 体验 | 像腾讯会议一样可选麦克风、纯语音全自动 | 设备检测弹窗 + 端点检测自动提交 |
| 对标 | 对标牛客界面与流程 | 视觉重构 + 押题卡 + 全程回放 |
| 深化 | 手动打断、结束词、术语纠偏、女面试官 | 逐项实现并配套测试 |
| 交付 | 别人要方便安装 | 跨平台安装器 + 全新目录实测 |
| 质跃 | "这不是 Agent，是固定输入输出" | Agent 运行时 + 多 Agent 团队 + MCP + 决策可视化 |

### 4.2 典型问题与解决（详见《04-测试报告》第 5 节）

最具代表性的三个：

1. **Chrome 语音识别 `network` 错误**——根因是内置识别依赖境外服务。绕过方式是"换个浏览器"，真正的修法是引入本地离线识别引擎。
2. **服务进程莫名退出**——根因是 Node 对未捕获异常的默认行为是终止进程。修法是增加进程级兜底，让 20 分钟的面试不会因为一次异常整体中断。
3. **面试永远结束不了**——根因是允许 Agent 动态换题后 `plan` 无限增长。修法是固化终止边界 `planSize`，收尾阶段禁用换题。

这三条的共同教训：**先找根因，再动手**。绕过的方案在演示现场一定会再出问题。

### 4.3 团队协作心得

- 分支保护与 PR 评审让"改坏主干"这件事没有发生过；
- 每个功能提交都写清楚"干了什么"，回溯问题时节省大量时间；
- 测试不是负担：语音链路的多个缺陷（黏连、空指针、状态残留）都是自动化测试先发现的。

## 7 结语

本项目从一个"能语音对话的网页"起步，最终交付了一套**Agent 自主决策、过程可见、能力可外接、离线可用**的模拟面试系统。过程中最重要的转变，是意识到"接了大模型的软件"不等于"Agent"——真正的区别在于：系统是否具备观察环境、调用工具、根据结果自主调整行为的闭环。

团队五人各司其职又紧密配合，在架构、语音、前端、内容、数据五个方向上各自深入，共同完成了从需求到交付的完整工程实践。
