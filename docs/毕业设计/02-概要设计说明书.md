## 1 引言

### 1.1 编写目的

本文档描述系统的总体架构、模块划分、数据组织、接口设计与关键运行流程，为详细设计与编码实现提供结构依据。

### 1.2 设计约束

1. **零第三方运行时依赖**：服务端仅使用 Node.js 内置模块，不依赖 npm 包，保证任意机器 clone 即可运行。
2. **单进程、单文件存储**：不使用外部数据库，数据以 JSON 文件持久化。
3. **可离线**：语音识别与基础面试流程必须在无网络时仍可运行。
4. **能力可外接**：核心业务能力需通过标准协议对外暴露。

## 2 总体架构

### 2.1 架构总览

系统采用浏览器 / 服务器（B/S）架构，服务端单进程，共分五层：

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层  public/                                               │
│   index.html（486 行）  style.css（664 行）  app.js（2143 行）  │
│   localasr.js（音频采集与流式上传）  vision.js（本地视觉分析）    │
│   交互：设备检测、实时收音状态、Agent 工作台、报告页、回放        │
├──────────────────────────────────────────────────────────────┤
│ 接口层  server.js（393 行）                                    │
│   原生 HTTP 服务 · 27 个 REST 路由 · 静态资源 · 鉴权与审计       │
├──────────────────────────────────────────────────────────────┤
│ 领域层  lib/（2297 行）                                        │
│   interview.js 面试状态机    agent.js 面试官 Agent 运行时        │
│   agentTeam.js 多 Agent 团队  llm.js 大模型适配与提示词          │
│   bank.js 题库与组卷          rag.js 检索增强（BM25）            │
│   asr.js 本地语音识别        terms.js 专业术语归一               │
│   db.js 存储与迁移            agentClient.js Python 端客户端     │
├──────────────────────────────────────────────────────────────┤
│ 数据层  data/                                                  │
│   db.json（会话/用户/历史）  questions/*.json（159 题）          │
│   knowledge/*.md（岗位知识库语料）  config.local.json（AI 配置） │
├──────────────────────────────────────────────────────────────┤
│ 开放层  mcp/（534 行）                                         │
│   mockmirror-mcp.js：零依赖 MCP Server（stdio），9 工具 / 3 资源 │
└──────────────────────────────────────────────────────────────┘
                            可选扩展
                 python-agent/（1938 行）：FastAPI 面试官 Agent 服务
```

### 2.2 模块职责划分

| 模块 | 文件 | 职责 | 对外接口 |
|------|------|------|----------|
| 路由与中间件 | server.js | HTTP 服务、路由分发、静态资源、登录鉴权、审计 | HTTP |
| 面试状态机 | lib/interview.js | 开场、组卷、作答流转、追问、收尾、报告编排 | start / ask / handleAnswer / finish |
| 面试官 Agent | lib/agent.js | 观察—思考—工具—决策循环，最多 3 步 | decide(session, ctx) |
| Agent 团队 | lib/agentTeam.js | 评估官 / 陪练官 / 出题官 | finalize / analyzeOne / coachPlan |
| 大模型适配 | lib/llm.js | 统一 chat 接口、JSON 模式、超时重试、离线引擎 | chat / isConfigured / modeLabel |
| 题库 | lib/bank.js | 加载、组卷（分层洗牌）、查题、统计 | init / buildPlan / findQuestion |
| 检索增强 | lib/rag.js | 语料切片、BM25 检索、上下文拼装 | init / search / context |
| 语音识别 | lib/asr.js | 本地流式识别引擎生命周期与分片识别 | available / push / finish |
| 术语归一 | lib/terms.js | 口语到专业术语纠正（130+ 词条） | normalize(text) |
| 存储 | lib/db.js | 读写、schema 迁移、原子写、备份 | init / saveSession / addHistory |
| MCP 服务 | mcp/mockmirror-mcp.js | 协议实现、工具与资源暴露 | stdio JSON-RPC |

### 2.3 模块依赖关系

```
server.js
   ├── interview.js ── agent.js ── llm.js
   │        │              └── rag.js / bank.js
   │        ├── agentTeam.js ── llm.js
   │        ├── bank.js
   │        ├── llm.js
   │        └── db.js
   ├── asr.js ── terms.js
   ├── llm.js ── agentClient.js ──(HTTP)── python-agent
   └── db.js ── data/db.json

mcp/mockmirror-mcp.js ──(HTTP 127.0.0.1:3000)── server.js
                      └──(只读文件)── data/questions、data/knowledge
```

> 设计要点：MCP Server 对**写状态**的操作一律转发给本机 HTTP 服务，保证会话数据只有一个写入方；对**只读**数据（题库、知识库）直接读文件，即使主服务未启动也能提供查询能力。

## 3 数据设计

### 3.1 存储方案

采用单文件 JSON 存储（`data/db.json`），理由如下：

1. 数据规模小（估算 25MB 级别），JSON 全量读写性能足够；
2. 无需安装与配置数据库，符合"clone 即跑"约束；
3. 便于备份、导出与人工排查。

**写入安全**：先写同目录临时文件，再原子重命名覆盖，杜绝"写一半崩溃导致整库损坏"。数据库带 schema 版本号，启动时自动检测并迁移，迁移前自动备份。

### 3.2 主要数据结构

| 结构 | 关键字段 | 说明 |
|------|----------|------|
| users[] | id、name、passHash、salt、createdAt | 口令加盐哈希，无明文 |
| sessions[] | id、userId、position、plan[]、planSize、rounds[]、status、agentMemory、agentTrace、report、startedAt、finishedAt | 一场面试的完整状态 |
| rounds[] | qIndex、question、answer、metrics、followUps[]、followCount | 逐题记录，支撑回放 |
| history[] | sessionId、position、score、finishedAt | 成长曲线数据源 |
| questions[] | id、type、text、keywords[]、points[]、hint | 159 题 |
| agentMemory | observations[]、weakPoints[]、strongPoints[]、askedIds[] | Agent 对候选人的长期记忆 |

### 3.3 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 终止边界 | 会话创建时固化 `planSize` | Agent 可动态换题，但不允许把面试无限延长 |
| 计划写入 | Agent 换题时覆盖 `plan[i]` 而非追加 | 保证统计与报告口径一致 |
| 轨迹记账 | 每轮决策开始时重置 `agentTrace` | 避免跨轮累积撑爆提示词导致模型退化 |
| 题库规模 | 3 岗位 × 约 53 题 = 159 题 | 覆盖技术 / 项目 / 场景 / 行为四类题型 |

## 4 接口设计

### 4.1 接口风格

统一为 JSON over HTTP，路径前缀 `/api/`，方法语义遵循 REST 约定；响应统一结构：

```json
{ "ok": true,  "data": { } }
{ "ok": false, "error": "错误描述" }
```

### 4.2 核心接口清单

| 接口 | 方法 | 入参要点 | 出参要点 |
|------|------|----------|----------|
| /api/interview/start | POST | 岗位、题量、JD（可选） | sessionId、开场白、首题、planSize |
| /api/interview/answer | POST | sessionId、qIndex、answer、metrics | nextLine、是否追问、下一题、进度、agent 轨迹 |
| /api/interview/prefetch | POST | sessionId、qIndex、answer 摘要 | 预取的下一句（供即时展示） |
| /api/interview/finish | POST | sessionId | report、transcript |
| /api/asr/chunk | POST | id、base64 PCM | final、interim、endpoint |
| /api/asr/end | POST | id | 最终文本 |
| /api/agent/analyze | POST | 岗位、题目、答案 | 深度评分、命中/缺失要点、建议 |
| /api/agent/roles | GET | — | 四个 Agent 角色与职责说明 |

### 4.3 MCP 对外接口

| 类型 | 名称 | 说明 |
|------|------|------|
| 工具 | list_positions | 列出岗位 |
| 工具 | start_interview / submit_answer / finish_interview | 主持一场完整面试 |
| 工具 | analyze_answer | 单条回答批改 |
| 工具 | get_report / get_history | 报告与历史 |
| 工具 | search_bank / knowledge_lookup / generate_questions | 题库与知识库能力 |
| 资源 | mockmirror://positions、mockmirror://bank/{position}、mockmirror://history | 只读资源 |
| 提示词 | mock_interview、review_answer | 可复用提示模板 |

## 5 关键流程设计

### 5.1 面试主流程

```
学生 ──选择岗位──▶ start
                    │ 组卷（分层洗牌，写入 planSize）
                    ▼
              面试官开场 + 第 1 题 ──TTS 朗读──▶ 学生
                    ▲                                │
                    │                                │ 开口作答（ASR 流式）
                    │                                ▼
                    │                        端点检测/结束词命中 → 自动提交
                    │                                │
                    │                                ▼
                    │                    Agent 决策循环（≤3 步工具调用）
                    │                                │
                    │         ┌──────────────────────┼──────────────────────┐
                    │         ▼                      ▼                      ▼
                    │       deepen 追问          switch 换题             next 下一题
                    └────────────────────────────────┘
                    │
                    ▼（进度达到 planSize）
              finish → 规则评分 → 评估官复核 + 陪练官计划（并行）→ 报告
```

### 5.2 语音识别链路

```
浏览器 AudioContext(16kHz)
   → ScriptProcessor 采集 PCM（2048 帧，约 160ms 一片）
   → base64 分片 ──POST /api/asr/chunk──▶ 本地 sherpa-onnx 流式识别器
   → 返回 final / interim / endpoint
   → 命中 endpoint（静音 0.8s）或结束词 → POST /api/asr/end
   → 术语归一（瑞迪斯→Redis）→ 提交作答

回退链：本地引擎不可用 → 浏览器 Web Speech → 均不可用则提示改用键盘
```

### 5.3 Agent 决策循环（核心）

```
1. 组装上下文：当前题 + 考察点 + 回答 + 已问题目 + 历史观察 + 进度
2. 大模型输出 { thought, action }
3. 执行工具：analyze_answer / search_knowledge / find_question
             / record_observation / adjust_plan
4. 工具返回作为 observation 回灌上下文
5. 重复 2~4，最多 3 步；最后一步强制输出 final
6. 轨迹下发前端「Agent 工作台」展示
7. 异常（无 LLM / 输出非法）→ 离线规则兜底，保证流程不中断
```

### 5.4 预取机制（性能关键）

学生开口作答的同时，服务端并发生成"下一步可能要说的话"，以学生答案前 60 字作为签名；学生提交时若签名一致则直接复用预取结果，把响应延迟从约 1120ms 压到 6ms。

## 6 AI 引擎抽象设计

系统支持三种引擎，通过配置切换，两端（Node 与 Python）共享同一份配置：

| 引擎 | 说明 | 适用场景 |
|------|------|----------|
| offline | 规则面试官，无外部依赖 | 断网演示、未配置大模型 |
| llm | OpenAI 接口兼容大模型（默认 DeepSeek） | 正式使用 |
| python | 转发至 Python Agent 服务 | 需要自定义 Agent 逻辑 |

统一入口 `llm.chat()` 屏蔽差异；引擎未配置时，面试开始接口返回明确提示（HTTP 428），避免"看起来在跑但其实是假 AI"。

## 7 非功能性设计

### 7.1 可靠性

| 措施 | 说明 |
|------|------|
| 原子写 | 临时文件 + 重命名，避免半截数据 |
| 进程兜底 | 未捕获异常与未处理拒绝只记录日志，不终止服务 |
| 调用重试 | 大模型网络类失败自动重试一次，仍失败降级离线 |
| 优雅退出 | 收到退出信号后保存并关闭 |
| 端口保护 | 被占用时输出可操作提示 |

### 7.2 安全

| 措施 | 说明 |
|------|------|
| 口令加盐哈希 | 不存储明文 |
| 密钥隔离 | 本地配置文件与备份目录已纳入 .gitignore |
| 路径穿越防护 | 规范化后校验目录前缀 |
| 请求体限流 | 超过 5MB 直接断开 |
| 隐私本地化 | 摄像头视频帧仅本机推理；语音识别可选本地引擎 |

### 7.3 可观测

健康检查接口 `/api/health` 返回服务状态、AI 引擎配置（不含密钥）、数据库统计（schema 版本、用户数、会话数、最近保存时间），便于部署探针与现场排障。

## 9 技术选型与理由

| 领域 | 选型 | 理由 |
|------|------|------|
| 运行时 | Node.js 内置模块 | 零依赖，跨平台，安装成功率最高 |
| 前端 | 原生 HTML/CSS/JS | 无构建步骤，改完刷新即生效，降低维护成本 |
| 语音识别 | sherpa-onnx 流式 zipformer（int8） | 可离线、RTF 0.041、模型体积可控；双语模型支持中英混说 |
| 语音合成 | 浏览器 Web Speech API | 零成本、支持本地音色 |
| 视觉分析 | MediaPipe 本地模型 | 不出本机，满足隐私要求 |
| 大模型 | OpenAI 接口兼容（DeepSeek） | 接口通用，换供应商只需改配置 |
| 开放协议 | MCP（stdio） | 零依赖可实现，主流 AI 工具均支持 |
| 存储 | JSON 文件 | 免安装、易备份、易排查 |
| 测试 | 自研断言脚本 + Playwright | 无需测试框架依赖，浏览器行为可验证 |
