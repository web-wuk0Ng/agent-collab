## 1 引言

### 1.1 编写目的

本文档面向指导教师、评审专家与项目组成员，明确「面镜 MockMirror」软件的功能边界、性能指标、数据要求与约束条件，作为概要设计、详细设计、编码实现与测试验收的统一依据。

### 1.2 项目背景

高校应届毕业生在求职过程中普遍面临三个现实困难：

1. **缺乏真实面试机会**：真实面试机会稀缺且不可重复，一次失误即失去机会，难以通过"多练"提升。
2. **反馈缺失**：即便参加真实面试，也几乎拿不到逐题的、可操作的改进建议，错误会被反复带到下一场。
3. **现有工具"不像面试"**：市面上的题库类产品以选择题和背诵八股为主，缺少"开口说、被追问、被评价"的完整闭环；已出现的 AI 面试产品多为云端黑盒，依赖境外语音服务，在国内网络环境下常不可用，且不具备可见的决策过程。

本课题以"让每个学生都能随时随地进行一场像真人的面试，并拿到可执行的提升方案"为目标，构建一套**可离线运行、Agent 自主决策、能力可外接**的 AI 模拟面试系统。

### 1.3 术语与缩略语

| 术语 | 说明 |
|------|------|
| ASR | Automatic Speech Recognition，自动语音识别，即"语音转文字" |
| TTS | Text To Speech，文字转语音，即"面试官发声" |
| RTF | Real Time Factor，实时率 = 识别耗时 / 音频时长，越小越快；本项目实测 0.041 |
| Agent | 具备"思考—调用工具—观察结果—再决策"循环的智能体，区别于固定脚本问答 |
| MCP | Model Context Protocol，模型上下文协议，用于让外部 AI 工具调用本系统能力 |
| RAG | Retrieval-Augmented Generation，检索增强生成，先检索本地知识库再生成回答 |
| 流式识别 | 边说边出字，不等用户说完即可返回中间结果 |
| 端点检测 | Endpoint Detection，通过静音时长判断"用户这句话说完了" |
| 观察者指标 | 由摄像头本地视觉模型统计的抬头率、视线、表情紧张度等行为指标 |

## 2 项目概述

### 2.1 建设目标

| 目标 | 具体内容 |
|------|----------|
| O1 真实感 | 全语音交互，面试官会追问、会打断、会换题，而非念脚本 |
| O2 可用性 | 国内网络环境可用；断网仍可完成面试（本地语音识别 + 规则面试官） |
| O3 智能可见 | 面试官的思考过程、工具调用、观察结论实时展示，而非黑盒输出一句话 |
| O4 可提升 | 逐题给出"该怎么答"，并生成一周练习计划，形成能力闭环 |
| O5 可外接 | 通过 MCP 协议对外暴露能力，可被第三方 AI 工具直接调用 |
| O6 易部署 | 零第三方运行时依赖，clone 后双击即可运行 |

### 2.2 用户特征

| 用户 | 特征 | 主要诉求 |
|------|------|----------|
| 在校学生（主要用户） | 有技术基础，缺乏面试经验与表达训练 | 反复练习、拿到具体改进建议 |
| 教师 / 就业指导人员 | 需要批量了解学生水平 | 查看历史记录与能力成长曲线 |
| 第三方 AI 工具（开发者） | 通过 MCP 接入 | 以编程方式主持面试、获取结构化评估 |

### 2.3 运行环境

| 类别 | 要求 |
|------|------|
| 客户端 | Chrome / Edge 90+（需支持 getUserMedia 与 Web Speech API），Windows / macOS / Linux |
| 服务端 | Node.js 18+（推荐 20 LTS），内存 ≥ 2GB |
| 语音识别 | 内置 sherpa-onnx 本地引擎（约 192MB 模型，首次启动自动下载） |
| 大模型 | 可选；支持 OpenAI 接口兼容服务（默认 DeepSeek），未配置时自动降级为离线面试官 |
| 网络 | 非必需；本地语音识别与离线面试官均可离线运行 |

### 3.2 核心用例规约

#### 用例 UC-01：进行一场全语音模拟面试

| 项目 | 内容 |
|------|------|
| 参与者 | 学生 |
| 前置条件 | 已登录；未配置大模型时系统提示需先完成 AI 接入（或选择离线演示模式） |
| 基本流程 | 1. 选择岗位 → 2. 设备与网络检测（可选麦克风）→ 3. 面试官开场并提问 → 4. 学生开口作答，界面实时显示收音状态 → 5. 说完（静音 0.8 秒或命中结束词）自动提交 → 6. 面试官 Agent 决策：追问 / 深挖 / 换题 / 下一题 → 7. 重复 4~6 直至计划题量完成 → 8. 自动生成评估报告 |
| 异常流程 | A1 麦克风无权限 → 引导在浏览器地址栏重新授权；A2 识别引擎不可用 → 自动回退浏览器语音识别；A3 大模型超时 → 自动重试一次，仍失败则降级为离线面试官并标注 |
| 后置条件 | 会话状态置为 finished，报告入库并计入历史 |

#### 用例 UC-02：面试官 Agent 自主决策（本系统核心）

| 项目 | 内容 |
|------|------|
| 参与者 | 系统（Agent） |
| 触发 | 收到一次候选人的完整回答 |
| 基本流程 | 1. 组装上下文（当前题、考察点、回答、已问题目、历史观察、进度）→ 2. 大模型输出 thought 与 action → 3. 执行工具（如 analyze_answer 分析命中与缺失要点）→ 4. 把工具返回作为 observation 回灌 → 5. 最多 3 步后输出 final（面试官要说出口的话）→ 6. 轨迹下发前端展示 |
| 终止条件 | 单轮最多 3 次工具调用；已追问过一次不再追问第二层；最后一题禁止换题 |
| 异常流程 | 大模型不可用或输出非法 → 离线规则兜底，保证面试不中断 |

#### 用例 UC-03：生成评估报告与提升计划

| 项目 | 内容 |
|------|------|
| 参与者 | 学生 |
| 触发 | 面试结束 |
| 基本流程 | 1. 规则引擎产出初版评分（多维度）→ 2. 评估官 Agent 调用统计工具复核逐题表现，输出"该怎么答"与加减分建议（限幅 ±15）→ 3. 陪练官 Agent 并行产出一周计划与针对性练习题 → 4. 汇总渲染报告页 |
| 异常流程 | Agent 输出占位内容（如"待核对数据后给出"）→ 校验不通过自动重试一次，仍不合格则保留初版报告 |

#### 用例 UC-04：通过 MCP 由外部 Agent 主持面试

| 项目 | 内容 |
|------|------|
| 参与者 | 第三方 AI 工具（如 Claude Desktop、Cursor） |
| 基本流程 | 1. 配置 MCP 服务器路径 → 2. 外部 Agent 调用 list_positions → start_interview → 3. 逐轮 submit_answer → 4. finish_interview 获取报告 → 5. 可继续调用 analyze_answer 对单条回答批改 |
| 约束 | 写状态操作统一转发至本机 HTTP 服务，保证会话数据单一写入方 |

## 4 非功能需求

### 4.1 性能需求

| 指标 | 要求 | 实测 |
|------|------|------|
| 语音识别实时率 | RTF ≤ 0.5（即 1 秒音频识别耗时不超过 0.5 秒） | 0.041 |
| 语音识别首字延迟 | ≤ 800ms | 约 320ms（160ms 分片 + 解码） |
| 面试官响应延迟 | 首次 ≤ 3s，命中预取后 ≤ 300ms | 1120ms → 6ms（预取命中） |
| 报告生成 | ≤ 30s | 8~15s |
| 本地语音识别内存占用 | ≤ 500MB | 约 260MB（int8 量化模型） |

> 说明：预取机制在学生开口作答期间即并行准备下一步内容，学生说完后几乎立即出结果，这是"对话不卡顿"的关键设计。

### 4.2 安全性需求

| 编号 | 需求 |
|------|------|
| S1 | 用户口令使用随机盐 + 哈希存储，禁止明文落盘 |
| S2 | 管理后台独立口令鉴权，关键操作写入审计日志 |
| S3 | 大模型密钥仅保存在本地配置文件，该文件与备份目录均已纳入 .gitignore，不进版本库 |
| S4 | 摄像头视频帧仅在本机内存完成推理，不上传、不落盘 |
| S5 | 静态资源目录穿越防护：对请求路径规范化后校验前缀，越界返回 403 |
| S6 | 请求体大小上限 5MB，超限直接断开，防止异常大包耗尽内存 |

### 4.3 可靠性需求

| 编号 | 需求 |
|------|------|
| R1 | 数据写入采用"临时文件 + 原子重命名"，写一半崩溃不会损坏数据库 |
| R2 | 任何未捕获异常只记录日志，不终止服务进程，避免面试中途整体中断 |
| R3 | 大模型调用失败自动重试一次；仍失败则降级为离线面试官，面试可继续 |
| R4 | 端口被占用时给出可操作的中文提示，而非抛出调用栈 |
| R5 | 接收到退出信号时保存数据后优雅退出 |

### 4.4 易用性与兼容性

| 编号 | 需求 |
|------|------|
| U1 | 无需安装数据库与中间件；Windows 双击 `启动面试.bat`，macOS/Linux 执行 `start.sh` |
| U2 | 所有批处理脚本使用纯 ASCII 字符，避免中文 GBK 解析导致的乱码报错 |
| U3 | 界面布局对标主流在线面试平台，关键操作（静音、打断、结束）位置固定 |
| U4 | 兼容 Chrome / Edge 双内核；语音识别具备"本地引擎 → 浏览器引擎"两级回退 |

### 4.5 可维护性需求

| 编号 | 需求 |
|------|------|
| M1 | 服务端零第三方运行时依赖（仅 Node 内置模块），避免安装失败与环境差异 |
| M2 | 题库为 JSON 数据文件，可由非开发人员通过管理后台导入维护 |
| M3 | 分层清晰：路由层（server.js）、领域层（lib/）、表现层（public/）、开放层（mcp/） |
| M4 | 关键功能配套自动化测试，可一键回归 |

## 5 数据需求

### 5.1 主要数据实体

| 实体 | 主要字段 | 说明 |
|------|----------|------|
| 用户 | id、用户名、口令哈希、盐、创建时间 | 登录与归属 |
| 会话 | id、用户、岗位、计划题量、状态、开始/结束时间、轮次、Agent 记忆与轨迹 | 一场面试的完整状态 |
| 轮次 | 题号、题目、原话、追问列表、行为指标 | 逐题记录，用于回放与评分 |
| 报告 | 总分、各维度得分、亮点、短板、建议、Agent 复核、陪练计划 | 评估结果 |
| 题库 | id、岗位、类型、题干、关键词、考察点、回答思路 | 159 题 |
| 知识库 | 岗位 Markdown 语料切片 | RAG 检索来源 |
| 历史 | 会话摘要列表 | 成长曲线数据来源 |

### 5.2 数据规模估算

按 100 名用户、每人 10 场面试、每场 6 题、每题回答约 400 字估算，总数据量约 25MB，单文件 JSON 存储可满足；数据文件按 schema 版本管理，具备升级与备份机制。

## 7 约束与假设

| 编号 | 内容 |
|------|------|
| C1 | 项目要求"clone 后双击即跑"，因此不引入数据库、Redis、消息队列等外部中间件 |
| C2 | 语音识别模型约 192MB，首次启动需联网下载；已提供镜像兜底与 `--skip` 跳过选项 |
| C3 | 大模型为可选项：未配置时使用离线面试官，功能可用但追问深度有限 |
| C4 | 中文神经语音音色依赖操作系统语音包，若目标机器无可自动降级到系统默认音色 |
| C5 | 视觉行为分析依赖摄像头授权，用户拒绝授权时该模块静默跳过，不影响面试主流程 |
