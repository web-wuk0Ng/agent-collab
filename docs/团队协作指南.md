## 一、这个项目是什么

- **做什么**：一个 Python Agent（智能体）服务，通过网页接口（FastAPI）对外提供对话能力
- **技术栈**：Python 3.11+ / FastAPI / pytest（测试）/ ruff（代码检查）
- **怎么合作**：所有人不直接改 `main` 分支，每人从 `main` 拉自己的分支写代码，写完发 Pull Request（PR），至少 1 名队友审核通过才能合并

> **第一次接触 Git？** 只需要记住三句话：
> 1. `main` 是"正式版"，不许直接改
> 2. 每个任务开一个自己的"分支"（副本），随便造
> 3. 造完了发 PR 请队友检查，通过才合进 `main`

## 二、第一次准备环境（只做一次）

### 第 0 步：装两个软件

| 软件 | 下载地址 | 说明 |
|------|---------|------|
| Git | <https://git-scm.com/downloads> | 管代码版本的工具 |
| Python 3.11+ | <https://www.python.org/downloads/> | 安装时**勾选 "Add Python to PATH"** |

装完打开终端（Windows 用 PowerShell，Mac 用 Terminal），验证一下：

```bash
git --version     # 显示版本号就是装好了
python3 --version # 显示 3.11 以上就行
```

### 第 1 步：把代码下载到电脑（克隆）

先让队长把你的 GitHub 账号加为协作者（否则下载后改了也传不上去）。然后：

```bash
git clone https://github.com/web-wuk0Ng/agent-collab.git
cd agent-collab
```

> 💡 克隆 = 把整个项目（含全部历史记录）复制到你电脑。以后只需要 `git pull` 更新。

### 第 2 步：告诉 Git 你是谁（只做一次）

```bash
git config --global user.name "你的GitHub用户名"
git config --global user.email "你GitHub绑定的邮箱"
```

> 邮箱一定要用 GitHub 绑定的那个，这样提交记录才能显示你的头像。

### 第 3 步：创建独立环境并装依赖

```bash
# 先进入 Python 服务目录（重要！）
cd python-agent

# 创建一个叫 .venv 的"独立房间"，项目的包都装在里面，不污染电脑
python3 -m venv .venv

# 进入这个房间（每次新开终端都要重新执行这一条！）
source .venv/bin/activate        # Mac/Linux
.venv\Scripts\activate           # Windows

# 装项目需要的包
pip install -r requirements.txt -r requirements-dev.txt
```

> ✅ 成功标志：终端最前面出现 `(.venv)` 字样。

### 第 4 步：验证环境没问题

```bash
pytest
```

看到 `passed` 字样（全部绿灯）就说明一切正常 🎉 环境搭建完成！

## 三、每日开发流程（超短版）

**开工：**

```bash
git checkout main                 # 1. 回到 main
git pull origin main              # 2. 拉最新代码
git checkout -b feat/功能名        # 3. 开自己的分支
```

**干活（改代码 → 反复）：**

```bash
git add 改过的文件名               # 4. 暂存改动
git commit -m "feat: 干了啥"      # 5. 存档（写清楚干了啥）
```

**收工（提交给队友审核）：**

```bash
git push -u origin feat/功能名    # 6. 推到 GitHub
# 7. 打开 GitHub 仓库页面，点黄色的 "Compare & pull request" 按钮
# 8. 填写 PR 描述，请队友 Approve，通过后点 "Squash and merge"
```

## 四、详细步骤解释（每个命令在干嘛）

### 4.1 分支怎么取名

| 前缀 | 用来做 | 例子 |
|------|--------|------|
| `feat/` | 新功能 | `feat/tool-registry` |
| `fix/` | 修 bug | `fix/chat-timeout` |
| `docs/` | 只改文档 | `docs/readme` |

### 4.2 提交信息（commit message）怎么写

格式：`类型: 一句话说清干了什么`

```
feat: 增加天气查询工具        ✅
fix: 修复对话超时问题          ✅
update                       ❌ 谁看得懂？
修改了一些东西                ❌ 修改了啥？
```

类型就 6 个：`feat`(新功能) `fix`(修bug) `docs`(文档) `refactor`(重构) `test`(测试) `chore`(杂活)

### 4.3 为什么要 `git pull` 再开分支？

分支是从当前代码"分叉"出来的。如果别人的新代码已经进了 main 而你用的是旧代码，你的分支就落伍了，合并时会冲突。所以**每次开工先 pull**。

### 4.4 合并后清理（好习惯）

```bash
git checkout main
git pull origin main
git branch -d feat/功能名          # 删掉本地已合并的分支
git push origin --delete feat/功能名  # 删掉 GitHub 上的分支
```

## 五、Code Review 互相审核

### 你提交了 PR，等审核

- PR 页面底部 **Checks** 栏出现绿勾 ✅ = CI（自动跑 lint 和测试）通过
- 有队友点了 **Approve** 后，点 **Squash and merge** → **Confirm squash and merge**
- 合并后 GitHub 会提示 Delete branch，点掉即可

### 你审核别人的 PR

1. 打开 PR → **Files changed** 标签页，逐行看改动
2. 鼠标悬停在某行 → 点蓝色 ➕ → 写评论
3. 看完给结论（右上角 Review changes）：
   - **Approve**：没问题，同意合并
   - **Request changes**：有问题，需要作者改完再看
   - **Comment**：只是聊聊，不算审核意见
4. 审核原则：**对代码不对人**；看不懂就问，不放心就说

> ⚠️ 注意：任何人都不能也不该绕过审核直接改 main，这是团队互相信任的基础。

## 六、出错了怎么办（急救包）

### ❓ `git push` 被拒绝（rejected）

说明远程有新代码，你基于旧代码。补救：

```bash
git pull --rebase origin main     # 把你的提交"搬"到最新代码之上
# 若提示冲突，去用编辑器改冲突文件，然后：
git add 冲突文件
git rebase --continue
git push
```

### ❓ 改乱了还没提交，想恢复

```bash
git restore 文件名        # 撤销这个文件未提交的修改（不可恢复，慎用）
```

### ❓ commit 信息写错了（还没 push）

```bash
git commit --amend -m "正确的信息"
```

### ❓ 想撤销最后一次提交但保留代码

```bash
git reset --soft HEAD~1   # 代码还在，重新 commit 即可
```

### ❓ 提交了不该提交的文件（如 .env 密钥）

立刻找队长处理，不要自己 force push。

### ❓ `pytest` 报 ModuleNotFoundError

多半是没激活虚拟环境：`source .venv/bin/activate` 后再跑。

### ❓ 实在搞不砸了

```bash
git stash        # 把当前乱七八糟的改动先收起来
git status       # 确认干净了
# 然后在群里求助，别硬删重来
```

### 🚫 绝对禁止

- 直接 push 到 `main`（仓库已上锁，别试了）
- `git push --force` 强推共享分支
- 提交 `.env`、密码、密钥、大文件
- 一个 PR 塞多个不相关的改动

## 七、项目结构与规矩

```
agent-collab/
├── server.js / lib/ / public/   # ① 面镜 MockMirror 面试系统（Node，主交付物）
├── data/                        #   岗位题库与知识库语料（与 Python 端共享）
├── 启动面试.bat / start.sh       #   一键启动脚本
├── python-agent/                # ② Python Agent 服务（本次实训的协作开发区）
│   ├── src/agent_project/       #   源代码主包
│   │   ├── core/                #     Agent 核心逻辑（改动需 2 人审核）
│   │   ├── agents/              #     具体 Agent 实现（一人一个 Agent，认领制）
│   │   ├── knowledge/           #     知识库检索
│   │   ├── tools/               #     工具集（一人一工具，认领制）
│   │   └── api/                 #     FastAPI 接口层
│   ├── tests/                   #   测试：写了功能必须配测试
│   ├── requirements*.txt        #   依赖清单（改前在群里说一声）
│   └── pyproject.toml           #   工具链配置（ruff/pytest）
├── docs/                        # 文档（含本文）
├── .github/                     # CI 配置、PR/Issue 模板（一般不用动）
└── CONTRIBUTING.md              # 详细协作规范（和本文配套）
```

**三条团队规矩：**

1. **测试必须过**：CI 不绿不合并，新功能必须带测试
2. **代码必须过 lint**：提交前跑 `ruff check src tests && ruff format src`
3. **改公共文件先吭声**：`requirements.txt`、`pyproject.toml`、CI 配置改动先在群里打招呼
