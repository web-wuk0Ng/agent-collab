# 添加自己的面试题

在网页顶部进入「知识库」，选择岗位后，使用下方「添加自己的面试题」。这属于个人本地练习功能，不需要管理员。

## 操作步骤

1. 点击「下载标准模板」，获得当前岗位的 UTF-8 JSON 文件。
2. 用 VS Code 等文本编辑器打开。保留顶层字段，替换 `questions` 中的示例；一份文件可放 1–200 题。
3. 点击「选择 JSON 文件」，也可粘贴 JSON 后点「校验并预览」。检查目标岗位、预计新增数、重复数和题目预览。
4. 点击「保存到本地题库」。显示「已保存到本机」后才算完成；文件选择或预览都不会写入。
5. 新题可被下场面试抽取，`reference` 和考察点会立即进入 RAG。正在进行的面试不会被强行换题。

如果编辑了预览后的 JSON，或别处已修改题库，需要重新校验。导入只追加，不覆盖已有题。重复导入同一个文件不会增加重复题；相同题干使用不同 ID 也会跳过。

## 标准 JSON 示例

```json
{
  "schemaVersion": 1,
  "position": "java-backend",
  "questions": [
    {
      "id": "my_timeout_001",
      "type": "project",
      "stage": "core",
      "text": "介绍你怎样定位项目中的接口超时，并验证解决方案？",
      "keywords": ["超时", "监控", "验证"],
      "points": ["给出定位证据", "说明重试和幂等边界", "用改动前后的数据验证"],
      "hint": "按背景、定位过程、解决方案和结果展开，避免只列技术名词。",
      "reference": "接口超时应区分连接、读取和整体请求期限。重试要限制次数并检查操作是否幂等；通过成功率、延迟分位数和日志确认改动效果，不能只凭平均耗时判断。",
      "sources": []
    }
  ]
}
```

## 字段规则

| 字段 | 是否必填 | 格式与含义 |
|---|---|---|
| schemaVersion | 是 | 数字 `1`，不能写成字符串 |
| position | 是 | `java-backend`、`python-algo`、`web-frontend` 之一；按文件内此字段决定目标岗位 |
| questions | 是 | 1–200 个题目对象；单岗位最多 3000 题 |
| id | 是 | 岗位内唯一，1–64 字符，仅英文、数字、下划线、短横线；建议使用自己的前缀 |
| type | 是 | `tech` 技术、`project` 项目、`scenario` 场景、`behavior` 行为 |
| stage | 是 | `warm` 热身、`core` 核心、`deep` 深挖 |
| text | 是 | 题干，5–600 字符 |
| keywords | 是 | 1–12 个关键词，每项 1–300 字符，供回答分析使用 |
| points | 是 | 1–12 个考察点，每项 1–300 字符；描述评估标准，避免只给空泛结论 |
| hint | 是 | 回答思路，5–1200 字符 |
| reference | 是 | 30–6000 字符的参考材料；说明原理、适用条件和边界，是新增题的 RAG 依据 |
| sources | 否 | 最多 8 个 HTTP/HTTPS 来源链接；自己总结的项目题可用空数组。链接只作溯源，系统不会自动爬取链接内容 |

字符长度按程序中的字符串长度校验。JSON 不支持注释和尾逗号。推荐文件不超过 2 MB；后端整个请求上限为 5 MB。

## 题库与 RAG 的区别

题库决定「可以问哪些题」，RAG 为面试官提供「依据什么追问和评估」。当前检索使用本地 BM25：既检索 `data/knowledge/*.md`，也检索题目中的 `reference`、关键词和考察点。增加题干而不给参考材料，只能增加题目数量，不能充分扩展知识依据，因此导入格式要求填写 `reference`。

当前三个岗位共 **213 题**：Java 后端 72 题、Python/算法 70 题、Web 前端 71 题。本次新增 54 题，均附参考材料与来源；内容为根据公开官方文档整理的练习题，不标称某公司的真实面试题。详细来源见 [题库来源](question-sources.md)。

Node 服务导入后立即重建检索索引。可选 Python Agent 的知识库在后续查询时检查语料文件变化并重新加载，两端使用同一份本地题库。

## 保存位置、备份与常见错误

- 保存到项目 `data/questions/<position>.json`。不需要安装数据库，不上传题库文件到第三方服务；面试时被检索到的参考片段会随面试上下文发送给你配置的大模型。
- 写入前保留同目录 `.json.bak`，通过 `.json.tmp` 原子替换。备份仅保留上次版本，多次导入会轮换；重要材料请自行另存。面试历史仍独立保存在 `data/db.json`。
- 字段错误：提示具体题号与字段。整批校验通过前不写入，修复后重新预览。
- ID 冲突：同一 ID 对应不同题干会拒绝整批导入。更换新题 ID；导入不承担修改旧题功能。
- 全部重复：新增数为 0，保存按钮保持禁用，无需反复保存。
- 已保存但暂未问到：抽题会兼顾题型和难度；导入不意味着下一题必然就是它。可在知识库用独特关键词检查 RAG 命中，并开始下一场面试。
- 手动编辑磁盘题库后请重启 Node 服务。手动改文件前自行备份并保证 JSON 合法；网页导入会自动完成校验和索引更新。

可供编辑器使用的正式 JSON Schema 位于 `public/templates/question-import.schema.json`；下载的模板是可直接修改并导入的示例。
